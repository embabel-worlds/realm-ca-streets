2 · The questions

Every panel runs a saved view by name through the app runtime (embabel.views.invoke). The views this page calls: CaPlaceDossier (the map and the dossier card — deliberately excludes the alert join so first paint stays fast), WhoRepresentsMe, AffordabilityGap, PartyLedger, SplitRepresentation, AirVsIncome, AlertsAtMyMPs (which owns the alert fetch; the dossier's alert pill is derived from its rows), AirQualityNow, and RiversNearMe. Adding a place by postal code calls gateway.represent.representPostcode once, then gateway.repository.createEntry. Adding a place by NAME calls gateway.nrcanGeolocator.nrcanGeolocate (NRCan place-name search), then gateway.represent.csdForPoint and gateway.represent.mpForPoint for the census key and the riding, then createEntry — such a place has no postal code, so its full representative slate stays empty (the page says so in place). No other calls are made.

The dossier view — the exact query that runs:

MATCH (p:CaPlace)
OPTIONAL MATCH (p)-[:HAS_SEAT]->(s0:CaSeat)
WITH p, collect(s0)[0] AS s
OPTIONAL MATCH (p)-[:HAS_POPULATION]->(pop:CaPopulation)
WITH p, s, max(toFloat(pop.value)) AS population
OPTIONAL MATCH (p)-[:HAS_MEDIAN_AGE]->(ma:CaMedianAge)
WITH p, s, population, max(toFloat(ma.value)) AS medianAge
OPTIONAL MATCH (p)-[:HAS_HOUSEHOLD_INCOME]->(inc:CaHouseholdIncome)
WITH p, s, population, medianAge, max(toFloat(inc.value)) AS medianHouseholdIncome
OPTIONAL MATCH (p)-[:HAS_DWELLING_VALUE]->(dv:CaDwellingValue)
WITH p, s, population, medianAge, medianHouseholdIncome, max(toFloat(dv.value)) AS medianDwellingValue
OPTIONAL MATCH (p)-[:HAS_UNEMPLOYMENT]->(un:CaUnemployment)
WITH p, s, population, medianAge, medianHouseholdIncome, medianDwellingValue, max(toFloat(un.value)) AS unemploymentRate
OPTIONAL MATCH (p)-[:HAS_AIR]->(a:AirQualityObs)
WITH p, s, population, medianAge, medianHouseholdIncome, medianDwellingValue, unemploymentRate, max(toFloat(a.aqhi)) AS worstAqhi
OPTIONAL MATCH (p)-[:HAS_WEATHER]->(w0:LocalWeather)
WITH p, s, population, medianAge, medianHouseholdIncome, medianDwellingValue, unemploymentRate, worstAqhi, collect(w0)[0] AS w
RETURN p.name AS place, p.city AS city, p.province AS province, p.postalCode AS postalCode,
       toFloat(p.latitude) AS latitude, toFloat(p.longitude) AS longitude,
       s.riding AS riding, s.mp AS mp, s.party AS party, s.photo AS photo, s.email AS email, s.gender AS gender,
       population, medianAge, medianHouseholdIncome, medianDwellingValue,
       unemploymentRate, worstAqhi,
       toFloat(w.temperature) AS temperatureC, w.condition AS condition, w.conditionFr AS conditionFr
ORDER BY place LIMIT $limit

Split representation — the join and the aligned definition (a shared party-name stem, nothing more):

MATCH (p:CaPlace)-[:HAS_REP]->(f:ElectedRep {office:'MP'})
MATCH (p)-[:HAS_REP]->(pr:ElectedRep)
WHERE pr.office IN ['MPP','MLA','MNA','MHA']
RETURN p.name AS place, f.name AS mp, f.party AS federalParty,
       pr.name AS provincialRep, pr.office AS provincialOffice, pr.party AS provincialParty,
       any(stem IN ['Liberal','Conservative','New Democratic','Green']
           WHERE f.party CONTAINS stem AND pr.party CONTAINS stem) AS aligned
ORDER BY aligned, place LIMIT $limit

The affordability gap — the ratio and its null rule:

MATCH (p:CaPlace)
OPTIONAL MATCH (p)-[:HAS_DWELLING_VALUE]->(d:CaDwellingValue)
WITH p, max(toFloat(d.value)) AS dwelling
OPTIONAL MATCH (p)-[:HAS_HOUSEHOLD_INCOME]->(i:CaHouseholdIncome)
WITH p, dwelling, max(toFloat(i.value)) AS income
RETURN p.name AS place, p.city AS city, p.province AS province,
       dwelling AS medianDwellingValue, income AS medianHouseholdIncome,
       CASE WHEN income IS NULL OR income = 0 OR dwelling IS NULL THEN null
            ELSE round(10.0 * dwelling / income) / 10.0 END AS yearsOfIncomePerHome
ORDER BY yearsOfIncomePerHome IS NULL, yearsOfIncomePerHome DESC LIMIT $limit

3 · When it looks wrong

  • No AQHI at a Québec place is coverage, not clean air: the federal AQHI network does not include Québec, which runs its own IQA network. Elsewhere, no row means no monitoring station within ~0.7° of the place.
  • The alerts panel arriving after everything else is by design: alerts have the shortest cache (10 minutes) and the occasional cold fetch is paid there, never by the dossier.
  • "Alerts" empty is the answer you want — no active Environment Canada alert touches any watched place.
  • A place missing from Split representation means Represent carries no provincial member for that postal code (its municipal and provincial coverage varies) — not that the seat is vacant.
  • Census figures describe the whole municipality — Toronto's median household income covers 2.8 million people, not one street. Incomes are 2020; the unemployment rate is the census reference week of May 2021, mid-pandemic.
  • Null condition or temperature overnight is normal — some weather.gc.ca sites stop reporting current conditions for a few hours.
  • "Request failed" in any panel means the fetch itself failed, not that the answer is empty — the two are worded differently everywhere in this app, in both languages.

4 · What made this possible

Each panel is a saved view executed by name; the joins (census income under an MP's party, a live weather alert beside the member for the riding) are computed inside the query that fetches the rows, by an engine that fetches from Represent, StatCan and Environment Canada on demand and caches each at its own cadence. The realm also ships a warmLiveFeeds verb (and a 9-minute schedule, pending host activation) that re-traverses the live joins to keep those caches warm. There is no backend for this page, no ETL pipeline, and no mirror of any register — delete the app and nothing else changes; install the realm anywhere and the same page works over that world's places.
